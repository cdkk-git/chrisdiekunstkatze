Posted: August 28, 2026   |   Site Update Log

This update focuses on typography and legacy browser optimization across the site. Below is a thorough log of every change made today.

1. Custom typeface embedded. The site's custom font, Andrew, has been embedded directly into the page as a Base64-encoded @font-face declaration. This means the font travels with the HTML file itself and does not require an external file request, so it will render correctly even when the page is viewed offline or on a server with restricted file access. It has been applied site-wide, covering the body text, tables, and form inputs, with the original Georgia and Palatino Linotype serif stack retained as a fallback for any browser that cannot render embedded fonts.

2. Key headings converted to rendered images. The site logo, the main post title, and all post subtitles (including this one) have been converted from live text into small PNG images, individually rendered using the actual Andrew font glyphs. This guarantees pixel-perfect, identical typography across every browser, including Internet Explorer 4, which has no mechanism for loading embedded or linked custom fonts at all. Alt text has been preserved on every image for accessibility and for browsers with images disabled.

3. Site mascot embedded. The CDKK mascot icon has been resized to its intended 30x30 display size and embedded as a Base64 image directly beside the header logo, consistent with the site's compatibility-first, self-contained approach.

4. Internet Explorer 4 compatibility pass. Several CSS properties were reviewed and adjusted for older parsers: font-family names were unquoted where safer for legacy parsing, and a legacy overflow:auto fallback was added ahead of the newer overflow-x / overflow-y split properties, so scrolling degrades gracefully on engines that only understand the older single-property syntax. It's worth noting plainly: true IE4 cannot load Base64 data: URIs or embedded TrueType fonts under any configuration, since both technologies postdate that browser. Where the embedded font cannot load, IE4 will correctly fall back to its native serif fonts for body text, and will display the rendered heading images exactly as intended, since those are ordinary images rather than font-dependent text.

5. Copy proofread and corrected. Several typographical errors introduced by missing spaces were found and fixed throughout the existing blog copy, including "ensurethat," "andsuggestions," "focuced," "restrictionswithin," "thenew," "Netscape 4.0largely," and "sensationsthat." No wording or meaning was changed beyond these corrections.


Posted: August 8, 2026   |   New Changes and Compatibility Updates

Today marks the launch of the new official page for Chres' Castle. This update brings a fresh look and improved navigation, making it easier for visitors to explore our content. We have also ensured that the site is compatible with older browsers and devices, providing a seamless experience for all users.

We are experimenting with compatibility and accessibility features to ensure that our content is available to a wider audience. We welcome feedback and suggestions for further improvements. These experiments are focused on restrictions within the HTML 4.01 framework, and we are committed to maintaining the integrity of the new design while enhancing usability.

We are also integrating restrictions within Internet Explorer 8 and Netscape 4.0, largely provided by the PSP NetFront browser, for experimental purposes. This will allow us to test how our content performs on older platforms and ensure that our site remains accessible.
